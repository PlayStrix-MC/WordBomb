# WordBomb — документация для recode

> **Важно:** декомпилированные исходники старого плагина удалены из проекта. Этот файл остаётся справкой о поведении старой версии.

Этот файл — подробное описание плагина **WordBomb** (мини-игра «Bomb Party» на русских словах для Paper-сервера Minecraft).
Он написан, чтобы по нему можно было сделать **новую (recode) версию** плагина без повторного изучения декомпилированного jar.

> Источник: `src/` — декомпилированный `WordBomb.jar` (CFR 0.152, см. `src/summary.txt`).
> `word_bomb/` — рабочие данные плагина (соответствует `plugins/word_bomb/` на сервере).
> Строки в декомпилированном коде записаны юникод-эскейпами (`Иг...`) — это русский текст. Ниже я приводил их уже расшифрованными.
> Декомпилятор не восстановил исходные имена локальных переменных и часть синтаксического сахара (switch по строкам, try-with-resources), но логика сохранена.

---

## 1. Идея игры

Несколько игроков стоят по кругу вокруг арены. Игра по очереди выдаёт каждому **шаблон** — 2 или 3 буквы (префикс или суффикс случайного слова из словаря). Игрок обязан написать в чат **русское слово из словаря**, которое **содержит** этот шаблон, и не использованное ранее в этой игре. Если не успел за отведённое время — **выбывает**, на его месте появляется череп, а он переходит в режим наблюдателя. Последний оставшийся — победитель.

Всё сделано в виде голограмм (Display-сущности, по одной копии для каждого игрока): слово отображается над ареной и при смене «взрывается» на буквы-частицы; при выбывании над игроком поднимается череп.

Кроме самой игры в плагине есть **community-цикл** для словаря: игроки предлагают новые слова (голосуя), жалуются на плохие слова, администраторы принимают или блокируют их. Есть статистика побед и плейсхолдеры для PlaceholderAPI.

## 2. Правила и поток игры (как реализовано)

### 2.1 Вход в зону и экран
- Арена имеет **центр** (`event-center` в config.yml) и **зону радиуса 50 блоков** в мире `world` (мир захардкожен в `EventZoneManager`).
- Проверка каждые 20 тиков (`EventZoneManager.start`).
- Игрок, вошедший в зону → открывается голографический экран `MainScreen` (через `ScreenManager.createUI`) в точке `hologram` из config.yml.
- Игрок, вышедший из зоны → экран закрывается (`tryClose`); если он участвует в очереди, его **автоматически выводят** (`leaveGame`, но только если игра не идёт).
- При выходе с сервера — игрок удаляется из зоны и его экран закрывается (`EventZoneManager.onPlayerQuit`).

### 2.2 Очередь и автостарт
- Вступить: кнопка «Играть» на экране или `/wb join`. Выйти: кнопка «Выйти» (только вне игры).
- Нужно **минимум 2 игрока** (`GameSession.canStart`).
- Когда в очереди становится 2+ игрока → запускается **обратный отсчёт 20 секунд** (`checkAndStartCountdown`). Отсчёт виден на экране как `⌚ N`. Если игроков стало меньше 2 — отсчёт сбрасывается (`stopCountdown`, счётчик = -1).
- По истечении отсчёта вызывается `start()`.

### 2.3 Старт игры
- Состояние: `isActive = true`, `currentRound = 0`, `usedWords` очищается, создаётся `WordDisplay` в точке `центр + (0, 8, 0)`, создаётся `BossBar` (зелёный, «Игра начинается...») и отображается всем участникам.
- **Расстановка**: игроки телепортируются на окружность радиуса **10 блоков** вокруг центра; `Y = highestBlockY + 2`; каждый смотрит на центр (yaw/pitch вычисляются через atan2).
- **Заморозка**: у всех участников `MOVEMENT_SPEED = 0` и `JUMP_STRENGTH = 0` (разморозка возвращает захардкоженные 0.1 и 0.42).
- Запускается `spectatorChecker` (раз в секунду): наблюдатель, отошедший дальше **20 блоков** от центра, телепортируется обратно в центр с сообщением.
- Вызывается `nextRound()`.

### 2.4 Раунд и ход
- Очередь ходов — по кругу (`currentPlayerIndex`).
- В начале раунда (и при смене текущего игрока) текущему игроку выдаётся **шаблон** (`Dictionary.generateWordTemplate`, см. раздел 6.1).
- **Таймер хода**: `T = max(5, 20 − currentRound)` секунд (`startTimer`). Уменьшается раз в секунду. Последние 5 секунд — звук `BLOCK_NOTE_BLOCK_HAT` текущему игроку.
- Боссбар: `«<ник> | <шаблон> | <N>с»`, прогресс = `T / (20 − min(15, round))`.
- **Раунд завершён**, когда **каждый** оставшийся игрок хотя бы раз ответил в этом раунде (`roundCompleted` — все `true`). Тогда `currentRound++`, звук `BLOCK_NOTE_BLOCK_PLING` всем, новый раунд (`nextRound`).

### 2.5 Проверка слова (`EventListener.onSendChatMessage` → `GameSession.handleWord`)
Все сообщения игроков в чат во время игры **отменяются** (`event.setCancelled(true)`), в том числе от тех, кто не участвует. Далее по порядку:

1. Текст конвертируется из **английской раскладки в русскую** (`TextUtils.convertEngToRus`, таблица QWERTY→ЙЦУКЕН; например `ghbdtn` → `привет`).
2. Регулярка `[а-яА-Я]+`. **Внимание: `ё` не проходит** (см. раздел 9).
3. Слово должно **содержать шаблон** (`contains`, без учёта регистра).
4. Слово должно быть **в словаре** (`Dictionary.wordIsInDictionary`, ё нормализуется в е). Иначе — «Такого слова нет в словаре.».
5. Если слово принимается, его отправляют в главный поток (`runTask`) → `handleWord`:
   - проверяется, что игра активна и отправитель — **текущий** игрок (иначе молча выходит);
   - если слово уже было в этой игре (`usedWords`) → звук `BLOCK_NOTE_BLOCK_BASS` и «Это слово уже было использовано!»;
   - иначе: слово добавляется в `usedWords`, игрок помечается в `roundCompleted`, всем звук `ENTITY_PLAYER_LEVELUP`, `WordDisplay.updateWord` (старое слово взрывается), в чат: слово оранжевым, шаблон **красным**;
   - передача хода следующему (`nextPlayer` → новый шаблон ему), затем если раунд полный → `nextRound`, иначе `startTimer` и `notifyCurrentPlayer` («Ходит игрок: X. Шаблон: Y»).

Сообщения при отказе (тексты для воспроизведения): `Слово не подходит` (не кириллица / не содержит шаблон), `Такого слова нет в словаре.`.

### 2.6 Выбывание
- Срабатывает, когда `timeLeft <= 0` **или** игрок вышел с сервера во время игры (`handlePlayerQuit` → `eliminatePlayer`).
- `eliminatePlayer`:
  - всем участникам звук `ENTITY_GENERIC_EXPLODE`;
  - над игроком (радиус до 1.5 блока) появляется **череп** (`SkullParticle`) с цветом, интерполированным между `#FFCC45` и `#FF6545`;
  - игрок удаляется из `players`, его шаблон стирается, добавляется в `spectators`, режим → **SPECTATOR**, телепорт на `центр + (0, 10, 0)`;
  - если игроков осталось **1** → `endGame()`;
  - иначе: `currentRound++`, все флаги раунда сбрасываются, новый шаблон следующему, `startTimer`, сообщение «Новый раунд начинается!».
- Текст при таймауте: `Время вышло! <ник> выбывает!`.

### 2.7 Конец игры (`endGame`)
- Если остался один игрок: `WinnersManager.addWin(winner)`, сообщение «Победитель: <ник>!», звук `UI_TOAST_CHALLENGE_COMPLETE`.
- Иначе: «Игра окончена!», звук `ENTITY_WITHER_DEATH`.
- Всем участникам: «Всего было использовано слов: N». Наблюдателям возвращается SURVIVAL.
- Сброс: таймеры, боссбар, `WordDisplay`, все коллекции очищаются. Объект `GameSession` переиспользуется для следующей игры (создаётся один раз в `EventListener`).
- Слушатели (`GameStateListener`: `onGameStart`/`onGameEnd`) уведомляются — их подписывает `MainScreen`, чтобы обновить кнопку.

### 2.8 Выход и другие случаи
- Выход из игры вне зоны/во время игры: во время активной игры выход из очереди запрещён («Нельзя выйти во время активной игры!»).
- Выход с сервера во время игры — как выбывание (`eliminatePlayer`).
- Наблюдатель (уже выбывший) выходит → возвращается SURVIVAL, удаляется из `spectators`.

## 3. Словарь, предложения и жалобы (community-цикл)

Файлы: `dictionary.txt` (слова), `offers.txt` (голоса за предложения), `reports.txt` (жалобы на слова из словаря), `actions.log` (журнал модерации).

| Действие | Кто | Что происходит |
|---|---|---|
| `/wb offer <слово>` | любой | Голос игрока за слово, которого **нет** в словаре. Один игрок — один голос за слово. Запись в `offers.txt`. |
| `/wb offer-list` | любой | Топ-10 предложений по числу голосов. |
| `/wb report <слово>` | любой | Жалоба на слово, которое **есть** в словаре. Один игрок — одна жалоба на слово. Запись в `reports.txt`. |
| `/wb report-list` | любой | Топ-10 слов по числу жалоб. |
| `/wb accept <слово>` | админ | Слово из предложений добавляется в `dictionary.txt`, удаляется из `offers`. Лог: `accept`. |
| `/wb block <слово>` | админ | Слово должно быть в жалобах; оно удаляется из `dictionary.txt` и из `reports`. Лог: `block`. |
| `/wb add <слово>` | админ | Прямое добавление в словарь (дописывает строку в конец файла). Лог: `add`. |
| `/wb remove <слово>` | админ | Прямое удаление из словаря (первое вхождение). Лог: `remove`. |
| `/wb search [дата] [время] [игрок] [действие] [слово]` | админ | Поиск в `actions.log`. `none` — пропуск поля. Совпадение — подстрока. |

Нормализация слов: `toLowerCase()`, `ё → е`. Слова принимаются только из русских букв (`[а-я]`, в командах также `А-Я`).

Логи выводятся в чат в формате: `§e[дата]§f[время]§b[ник]§a[accept]§6[слово]` (цвета действий: accept — зелёный, block — красный, remove — тёмно-красный, add — тёмно-зелёный, прочее — белый).

## 4. Команды и права

Основная команда: `/wb`. Для не-игроков (консоль) — отказ «Эта команда только для игроков!».

| Команда | Право | Описание |
|---|---|---|
| `/wb join` | нет | Встать в очередь. |
| `/wb start` | **нет (по коду)** | Ручной старт. **Сломан** — см. раздел 9.1. |
| `/wb offer <слово>` | нет | Голос за новое слово. |
| `/wb report <слово>` | нет | Жалоба на слово из словаря. |
| `/wb offer-list` / `/wb report-list` | нет | Топ-10. |
| `/wb top` | нет | Топ-10 по победам. |
| `/wb accept <слово>` | `event_manager.event` | Принять предложение. |
| `/wb block <слово>` | `event_manager.event` | Заблокировать по жалобам. |
| `/wb add <слово>` / `/wb remove <слово>` | `event_manager.event` | Прямое редактирование словаря. |
| `/wb search ...` | `event_manager.event` | Поиск по журналу. |
| `/wb config setCenter` | `event_manager.event` | Центр арены = блок, на который смотрит админ (до 5 блоков), +(0.5, 1, 0.5). |
| `/wb config setHologram <x> <y> <z> <yaw> <pitch>` | `event_manager.event` | Позиция голограммы (мир `world`). |

Подсказка при неизвестной команде: `Неизвестная команда. Используйте: /wb <join|start|offer|report|offer-list|report-list|accept|block|add|remove|search|top|config>`.

Отдельной подкоманды «выйти» нет — выход из очереди только кнопкой на экране или выходом из зоны. Метод `leaveGame` существует, но команды для него нет.

Автодополнение (`CommandTabCompleter`):
- 1-й аргумент: `join, offer, report, offer-list, report-list, top` + (для админа) `start, accept, block, add, remove, search, config`;
- для `accept` — топ предложений; для `block` — топ жалоб; для `search` — даты из журнала + `none`; для `remove/report/add/offer` — подсказка `<слово>`; для `config` — `setCenter, setHologram`;
- для `search`: 3-й аргумент `none|HH:mm:ss`, 4-й — игроки из журнала, 5-й — `accept, block, remove, add`, 6-й — `none|<слово>`.

Право `event_manager.event` проверяется через `player.hasPermission` (`PermsManager`). Сам плагин «event_manager» в этом jar отсутствует.

## 5. Конфигурация и данные

### 5.1 `plugins/word_bomb/config.yml`
```yaml
event-center:        # центр арены
  world: world
  x: -451.5
  y: 71.0
  z: 6459.5
hologram:            # точка экрана MainScreen
  world: world
  x: -451.0
  y: 79.0
  z: 6489.0
  yaw: -180.0
  pitch: 0.0
```
- Если мир не найден или ключа нет → центр по умолчанию `(0.5, 0.5, 0.5)` в мире `world`; голограмма по умолчанию — центр `+ (10, 0, 0)`.
- Значения пишутся командами `/wb config ...` (через `GameConfig.saveConfig`).

### 5.2 `dictionary.txt`
- **Около 1 525 550 строк, 34 МБ**, кодировка UTF-8, одно слово на строку.
- Строки в основном в нижнем регистре, начинаются с `Ёжась`, `Ёжат`... (в файле есть заглавные — нормализация приводит к нижнему).
- Файл **не скачивается автоматически**: в `Dictionary.java` есть метод `downloadIfNotExists` с ссылкой на Google Drive (ID в коде), но он **нигде не вызывается**. Словарь нужно положить вручную в `plugins/word_bomb/dictionary.txt`.
- Если файла нет — `initialize()` логирует предупреждение, а `randomWordsList` остаётся `null` → NPE при первом `getRandomWord()`.

### 5.3 `offers.txt` и `reports.txt`
Формат одной строки: `слово:uuid1,uuid2,...` (UUID игроков, которые проголосовали/пожаловались). Пустой список — `слово:`.

### 5.4 `winners.txt`
Формат: `ник:число_побед`. Ключ — **ник**, не UUID (см. баги).

### 5.5 `actions.log`
Формат строки: `[yyyy-MM-dd][HH:mm:ss][ник][действие][слово]\n`.
Действия: `accept`, `block`, `add`, `remove`. Пример: `[2025-05-24][18:45:53][HAPSIEL_LOVE][accept][имя]`.

## 6. Ключевые алгоритмы

### 6.1 Генерация шаблона (`Dictionary.generateWordTemplate`)
1. Случайное слово берётся из **`randomWordsList` — первых 10 000 строк словаря** (`limit(10000)`), а не из всего словаря.
2. Размер шаблона: **2 буквы с вероятностью 90%, 3 буквы с вероятностью 10%** (`randomWordTemplateSize`), но не больше длины слова.
3. Случайно: **префикс** (`substring(0, n)`) или **суффикс** (`substring(len-n)`) — 50/50.
4. Антиповтор: хранится очередь последних **20 шаблонов** (`recentTemplates`, в нижнем регистре). Если шаблон уже в очереди — берётся новое слово; максимум **50 попыток**, после чего шаблон принимается как есть.
5. Слова короче 2 букв дают сам себя как шаблон.

### 6.2 Проверка слова в словаре (`Dictionary.wordIsInDictionary`)
- Сначала проверяется кэш `words` (HashSet — только **найденные** слова).
- Иначе **полный проход по файлу** `dictionary.txt` (`Files.lines(...).anyMatch`) с нормализацией каждой строки. Для 1.5 млн строк — заметно медленно, вызывается **в асинхронном потоке чата** на каждом новом (не найденном в кэше) слове. Ненайденные слова не кэшируются — повторный ввод опять читает весь файл.

### 6.3 Таймер и раунды (сводка)
- Ход: `T = max(5, 20 − currentRound)`.
- `currentRound` растёт при: завершении раунда (все ответили) и при каждом выбывании.
- Таймер хода перезапускается при каждом успешном ходе и при смене раунда.

### 6.4 Расстановка по кругу
`angle_i = i * 2π/N`, позиция `(cx + 10·cos, cz + 10·sin)`, блок — `getHighestBlockYAt(x,z)`, точка `+2` по Y, `+0.5` по X/Z. Yaw = `atan2(−dX, dZ)`, pitch = `−atan2(dY, horizontal)`.

### 6.5 Голограммы и экраны (UI)
- Вся UI-часть построена на **внешней библиотеке DisplayAPI** (`me.padej.displayAPI`, это отдельный плагин автора, в `src/` её нет). Классы, которые используются: `UIManager`, `WidgetManager`, `TextDisplayButtonWidget`, `TextDisplayButtonConfig`, `ItemDisplayButtonWidget`, `WidgetPosition`, `ComponentRectangle`, `DefaultSquare`, `Animation`, `ChangeScreen`, `Particle`, `DisplayAPI.particles` (список активных частиц, тикает), аннотация `@Main`, интерфейсы `Animatable`, `IDisplayable`, `IParentable`.
- `ScreenManager.createUI(player, ScreenClass)`: закрывает текущий экран игрока, создаёт экран через конструктор `(Player, Location, String, float)`, через 2 тика анимирует фон (масштаб `(40, 16, 1)` для `MainScreen` — больше, чем базовый `(10, 4, 1)`), вешает `onClose` и регистрирует экран в `UIManager`.
- `ScreenTemplate`: фон — `TextDisplay` с цветом `#0A0A0A` и альфой 200, видим **только зрителю** (`setVisibleByDefault(false)` + `viewer.showEntity`). Яркость 15/15. Позиции виджетов — относительно точки экрана (`right`, `up`, `depth` вектора взгляда).
- Кнопки: `TextDisplayButtonWidget` с **tolerance** (радиус попадания взглядом): 0.21 для текста ≤5 символов, 0.25 для ≤8, 0.42 для ≤12, 0.44 для длиннее (`calculateTolerance`). Наведение: увеличение до `(3,3,1)` за 3 тика.
- **MainScreen** (`@Main` — без кнопки «назад»):
  - счётчик игроков `☻ N` (позиция `(-0.45, 1.9)`), светло-голубой `#A1EFFF`;
  - таймер `⌚ N` или `⌚ -` (позиция `(-0.45, 3.1)`);
  - кнопка «Играть» (градиент `#008BF1 → #72DDFF`, позиция `(-0.45, 0.8)`, tolerance 1.7) или «Выйти» (градиент `#BF0012 → #FF0000`);
  - кнопки исчезают при идущей игре;
  - обновление счётчика/таймера раз в секунду (`BukkitRunnable`).

### 6.6 Визуальные эффекты
- **WordDisplay**: слово — `TextDisplay`-прямоугольник (`ComponentRectangle`, размер 10, чёрный фон, `Billboard.CENTER`), **текст посимвольно градиентом** `#FFCC45 → #FF6545`, жирный, яркость 15/15. Новое слово заменяет старое: старое **взрывается** — каждая буква создаёт `CharParticleExplode`.
- **CharParticleExplode** (по букве): жизнь `200–300` тиков; стартовая скорость `0.5–0.8`, направление — полная сфера (горизонт 360°, вертикальный угол до 60°), `+0.3` по Y; каждый тик: гравитация `−0.008` по Y, сопротивление `×0.98`, «покачивание» ±0.008 по X/Z. Столкновение с solid-блоком (шаг 0.2): по Y скорость `×−0.6`, по X и Z `×−0.8`. За 12 тиков до конца — уменьшение до 0 (`Animation`, 10 тиков).
- **SkullParticle** (череп `☠`): поднимается со скоростью `0.11` с затуханием `×0.9`; жизнь 100 тиков; на 5-м тике растёт до `5×`, на 88-м уменьшается до 0.
- Цвета: градиент слова `#FFCC45 → #FF6545` (интерполяция по индексу символа), у черепа — та же пара, но случайная точка между ними.
- Градиенты кнопок — через `ColorUtil.gradient(text, colors...)` (поцветная интерполяция по символам, минимум 2 цвета).

### 6.7 Боссбар и чат

## 9. Баги, странности и «подводные камни» (учесть в recode)

1. **`/wb start` сломан — инверсия условия.** В `EventListener.startGame`: `if (gameSession.canStart())` → «Недостаточно игроков! Нужно минимум 2.». То есть при **2+** игроках ручной старт отказывает, а при **<2** молча ничего не делает. Фактически игра стартует только автоотсчётом.
2. **Ход после выбывания текущего игрока уходит назад.** В `eliminatePlayer`: если индекс удаляемого `≤ currentPlayerIndex`, индекс уменьшается, поэтому следующим ходит **предыдущий** игрок, а не следующий (исключение — игрок с индексом 0). Проверить, задумано ли.
3. **Словарь для шаблонов — только первые 10 000 строк** (`limit(10000)`), а проверка принадлежности — по всему словарю. Случайные шаблоны получаются из узкого подмножества.
4. **Производительность проверки слов.** Каждое новое (не из кэша) слово → полный проход 34 МБ файла в потоке чата. Ненайденные слова не кэшируются. Для recode: загрузить словарь в `HashSet`/`trie` при старте.
5. **Ё.** Регулярка чата `[а-яА-Я]+` не пропускает `ё`, хотя словарь нормализует `ё → е`. Слова с `ё` в игре фактически не принимаются, а `/wb offer` тоже отклоняет `ё`.
6. **Чат во время игры полностью перехватывается** (`setCancelled(true)`) — и для не-участников тоже. Сообщения не-участников проходят валидацию и могут получить «Слово не подходит».
7. **Гонки записи файлов.** `addWord`/`removeWord` переписывают/дописывают `dictionary.txt` без блокировки; `saveHistory` перезаписывает `offers/reports` целиком при каждом голосе. При параллельных командах возможна потеря данных.
8. **`removeWord` удаляет только первое вхождение**; `WordsManager.addWord/removeWord` — просто обёртки.
9. **`winners.txt` ключуется ником**, а не UUID: смена ника = потеря статистики.
10. **Подписка `MainScreen` на `GameStateListener`** делается только если `GameSession` уже существует в момент создания экрана. Если экран открыт до первого `/wb join`, то `onGameStart/onGameEnd` для него не придут (кнопка обновится только после действий самого игрока).
11. **Права.** `/wb join`, `/wb start`, `/wb offer`, `/wb report` и просмотр топов доступны без права. Право `event_manager.event` нужно только для модерации и настроек.
12. **Разморозка** возвращает захардкоженные `0.1` и `0.42`, а не исходные значения атрибутов игрока.
13. **Мир `world` захардкожен** в `EventZoneManager`, `CommandHandler.setHologram`, `GameConfig` (fallback). Для recode вынести в конфиг.
14. **Таймеры и константы захардкожены**: отсчёт 20 с, ход `max(5, 20−round)`, зона 50, радиус круга 10, наблюдатель 20, высота наблюдателя +10, шаблоны 2/3 (90/10), история 20, попытки 50, пул 10 000, радиус взрыва черепа 1.5.
15. **Мёртвый код**: `GameTimer` (все методы пусты), `PlayerManager.giveWordTemplateForPlayer` (пусто), `PlayerSkinTexture` (пусто), `Dictionary.downloadIfNotExists` (не вызывается; ссылка на Google Drive в коде), `Dictionary.getRandomWordForTemplate` (дубль `getRandomWord`), `EventListener.leaveGame` без команды.
16. **Нормализация в `usedWords`** не делает `ё → е`, но ё сейчас всё равно не проходит.
17. **`GameSession.getTemplate()`** падает с `IndexOutOfBoundsException`, если список `players` пуст (`getCurrentPlayer()` берёт `players.get(currentPlayerIndex)`). Вызывается из чата только когда игра активна, но в recode стоит защититься.
18. **Поиск в `actions.log`** — по подстроке (`contains`), а не по точному совпадению.
19. **Таймер хода** в `startTimer` первым тиком уже уменьшает `timeLeft`, поэтому ход фактически длится на ~1 с больше объявленного значения.
20. **Дубль логики**: `nextRound()` и блок в `eliminatePlayer` почти одинаковы — в recode объединить.

### 11.3 Предлагаемая структура (state machine)
```
WAITING ──(≥2 игроков)──► COUNTDOWN(20с) ──► ROUND/TURN ──(таймаут)──► ELIMINATION
   ▲                          │ (<2)               │ ▲                       │
   └──────────────────────────┘                    │ └──(≥2 живых)───────────┘
                                                   └─(ход выполнен)
ROUND/TURN ──(1 живой)──► ENDED ──► WAITING
```
Компоненты:
- `GameSession` (состояние + правила), без Bukkit внутри — тестируемо;
- `Dictionary` (in-memory `Set`, нормализация, пул для шаблонов, антиповтор);
- `TemplateGenerator` (2/3 букв, 90/10, префикс/суффикс, история 20, 50 попыток);
- `Storage` (словарь, предложения/жалобы, победы, журнал — по интерфейсу, можно SQLite);
- `EventZone` + `Hologram UI` (отдельно от логики);
- `Effects` (взрывы букв, череп, звуки).
